为什么 ΔE 徽章不加角标

ΔE 是从两个 hex 算出来的，没有可点击的来源。给它挂角标会让用户以为点得开。

「用量 推算」用虚线 + 斜体

计算类结论与引用类结论走两套视觉语言：引用是实心角标，推算是虚线 chip。

替代色号标注证据强度

现有实现把「同标准色号」和「跨品牌最近色」混排只按 ΔE 排序，两者可信度差别很大。

链接不放进种子表

672 条色号只存来源 ID，URL 集中在 sources.py。改链接只改一处，且自检能断言「引用的 ID 必须存在」——这是"不得编造"的机械保证。

推断组不给编号

编号只属于能被点击核实的来源。推断项写清楚「用了什么模型、锚点从哪来、怎么校准」。

3 · 核实抽屉（联网能力的正确落点）

只发送 {品牌, 色号} 文本，不发送任何位图。默认展示各源状态与耗时——这就是「检索过程可见」，而不是把 query rewrite 日志摊给用户。

2 个源响应，1 个超时，1 个被限流，1 个解析失败。官方与本地值 ΔE 0.00，无需修改。
「解析失败」≠「查无此色」

这两者含义相反，必须分开显示。合并成"未找到"会让用户以为这个色号不存在。

失败不改本地值

全部源失败时明确写「未能核实，当前值仍是 XX 来源于 YYYY-MM 的数据」，一字不改。这是最关键的回归测试断言。

缓存

慢变数据，TTL 90 天，缓存在 userdata/cache/，损坏时静默降级为未缓存。

4 · 低置信 / 数据过期态

初次上线时未标注数据会被集体压到「推定」档。建议第一阶段先显示为温和的「未标注来源」，数据补齐后再切严格置信度。
